# 대화 가지 관리 도구 설계

작성일 2026-11-23. 플러그인 이름 detour(`claude-`로 시작하는 이름은 Claude Code가 예약어로 거부한다).

## 만드는 이유

Claude Code로 기능을 개발하다가 궁금한 점이 생기면 그 자리에서 질문하게 된다. 질문이 꼬리를 물면 메인 작업으로 돌아가기 어렵고, 메인 대화에 작업과 상관없는 내용이 섞인다.

사용자가 지금 쓰는 방법과 방법별 문제는 다음과 같다.

| 지금 하는 일 | 문제 |
|---|---|
| 같은 대화에서 그냥 이어서 질문 | 메인 대화가 오염된다 |
| `/branch`(또는 `/fork`)로 갈라서 질문 | 갈라지기 전 지점으로 돌아가려면 `/resume` 목록에서 원래 세션을 직접 찾아야 한다. 귀찮고 잘 찾아지지 않는다 |
| `/btw`로 질문 | 도구를 쓸 수 없어서 코드를 열어 보지 못하고 답이 얕다 |

이 도구의 핵심은 왕복이다. 곁가지로 나가서 도구를 전부 쓰며 조사하고, 명령 한 번으로 갈라진 지점에 돌아온다. 곁가지 내용은 메인에 가져가지 않는다. 필요하면 사용자가 메인에서 직접 말한다. 가지 나무 그림은 돌아갈 곳을 찾는 수단이다.

## 목표

1. `/side [질문]`: 지금 지점에서 곁가지를 생성한다. 곁가지는 진짜 포크라서 도구를 전부 쓸 수 있다. 질문을 같이 적으면 곁가지의 첫 메시지로 보낸다.
2. `/back`: 묻지 않고 갈라진 메인 세션으로 바로 돌아간다. `/tree`로 옮길 때와 같다.
3. 곁가지에 있는 동안 입력창 위에 한 줄을 보여 준다. 지금 어느 곁가지에 있는지, 돌아가는 명령이 무엇인지 표시한다.
4. `/tree`: 옆 칸에 가지 나무를 띄운다. 가지를 고르면 그 세션으로 이동한다.
5. 기록은 Claude Code를 껐다 켜도 유지한다.

### 성공 기준

- 곁가지에 들어가는 데 명령 한 번이면 된다.
- 메인으로 돌아오는 데 명령 한 번이면 된다.
- 돌아온 메인에는 곁가지 대화가 한 줄도 들어가지 않는다.
- 메인에는 곁가지로 나갔다는 `/side` 입력 줄 하나만 남게 한다. 이 명령의 출력은 사용자에게만 보이고, 모델에게는 보내지 않는다(`isTextDisplayOnly`).
- `/resume` 목록을 뒤지지 않고 원래 세션에 돌아온다.

## 하지 않는 것

- 되감기(Esc 두 번, `/rewind`)로 한 세션 안에 생긴 가지는 1차 범위에서 그리지 않는다. 세션 기록에 부모 메시지 ID(`parentUuid`)가 있어서 나중에 붙일 수 있다.
- 메인과 곁가지를 동시에 돌리지 않는다. Claude Code 세션은 한 번에 하나만 활성 상태다.
- 곁가지에서 바뀐 파일을 메인으로 돌아갈 때 되돌리지 않는다. 대화만 가르고, 파일은 같은 폴더를 함께 쓴다.
- 곁가지 대화 전체를 메인에 합치지 않는다.

## 실패로 보는 경우

기술적으로 동작하더라도 아래에 해당하면 실패다.

- 돌아온 메인에 곁가지 대화가 섞인다.
- 돌아갈 곳을 찾으려고 결국 `/resume` 목록을 봐야 한다.
- 플러그인 때문에 기존 세션이 망가지거나, 설치하지 않았을 때와 Claude Code 사용법이 달라진다.

## 만드는 방식

| 방식 | 내용 | 대가 |
|---|---|---|
| A. Claude Code 플러그인 | Claude Code 안에서 명령, 옆 칸, 입력창 위 한 줄로 동작한다 | Claude Code 플러그인 기능에 기대야 한다 |
| B. Orca 플러그인 | Orca 옆 칸에 나무를 크게 그리고, 누르면 터미널에 `/resume <ID>`를 입력한다 | Orca 사용자만 쓸 수 있다. Orca 칸이 세션 기록을 읽을 방법이 아직 확인되지 않았다 |
| C. 독립 실행 프로그램 | `claude` 대신 실행하는 프로그램이 Claude Code를 띄우고 옆에 나무를 그린다 | 다른 전체 화면 터미널 프로그램을 감싸는 작업이 까다롭다. 세션 기록 내부 형식에 기대야 한다 |

사용자가 고른 것: **A를 먼저 만들고, B는 A 위에 덧붙인다.** 저장소 하나에 둘 다 둔다. C는 A가 막힐 때 쓸 대안이었는데, 시험에서 A가 통과해서 쓰지 않는다.

## 사용자가 정한 것

- 돌아올 때 곁가지 내용은 가져가지 않는다. `/back`과 `/tree` 모두 묻지 않고 옮긴다.
- A 먼저, B는 그다음이다.
- Claude가 일하는 도중에 `/side`를 치면 작업이 끝날 때까지 기다렸다가 가른다. 급하면 사용자가 Esc로 직접 멈춘다. Esc 뒤에는 Claude Code가 사용자가 다시 입력할 때까지 플러그인이 넣는 명령을 받지 않으므로, 입력창에 `/side <질문>`을 다시 채워 두고 Enter 한 번으로 갈라지게 한다.
- 저장소를 새로 만들고 git도 새로 시작한다.

## 시험으로 확인한 것

2026-11-22에 Claude Code 2.1.330에서 버릴 시험용 플러그인으로 확인했다. 지금 쓰는 세션과 따로 Claude Code를 하나 더 띄워서 시험했다. 시험 코드는 임시 폴더에서 쓰고 지웠다.

| 항목 | 결과 |
|---|---|
| 플러그인에서 `/branch`, `/resume <ID>` 실행 | 된다. 메인에서 갈라 곁가지에서 메시지를 보낸 뒤 메인으로 돌아와 직전 메시지를 물으니, 갈라지기 전 메시지를 답했다. 메인은 곁가지 내용을 모른다 |
| 터미널에서 옆 칸 열기 | 된다. `$.ui.open`이 `isPlaced: true`로 답했고 화면에 그려졌다 |
| 메인에 메모 붙이기 | 된다. `$.session.append`로 붙인 메모를 모델이 읽고 그대로 인용했다 |
| 곁가지의 곁가지 | 된다. 새 세션 기록마다 `forkedFrom: { sessionId, messageUuid }`로 부모가 남는다 |

## 제약

- **명령 안에서 명령 실행 금지.** `command.run` 훅 안에서 `$.command.run`을 부르면 엔진이 거부한다("it would wait on the turn this hook is holding"). 명령은 할 일을 대기열에 적기만 하고, `session.start`에서 시작한 `$.clock.every(500)` 타이머가 실행해야 한다. `$.clock.sleep(300)` 뒤에 실행하는 방식도 시험에서 동작했다.
- **옆 칸 자리.** 사용자가 명령으로 연 칸은 터미널 폭과 상관없이 뜬다. 자동으로 연 칸은 터미널 폭이 144칸 이상일 때만 배치된다. Orca에서 화면을 나누면 터미널이 이보다 좁아질 수 있다. 그래서 평소 표시는 입력창 위 한 줄로 하고, 나무는 `/tree`로 열 때만 띄운다.
- **세션 기록 형식은 비공식이다.** `forkedFrom`과 `parentUuid`는 문서에 없는 내부 형식이라 Claude Code 업데이트로 바뀔 수 있다. 그래서 `/side`로 만든 가지는 플러그인이 직접 기록하고, 그 기록을 기준으로 한다. `forkedFrom`은 사용자가 `/branch`로 직접 가른 세션을 나무에 함께 보여 줄 때만 보조로 쓴다. 형식이 바뀌어도 그 보조 표시만 빠지고 `/side`와 `/back`은 계속 동작해야 한다.
- **`/resume`은 세션의 마지막 지점으로 돌아간다.** 곁가지에 있는 동안 메인이 그대로였다면 갈라진 지점과 같다. 사용자가 그사이 메인으로 가서 대화를 더 했다면 마지막 지점으로 돌아가게 되므로, 이 경우 몇 개 메시지가 더 진행됐는지 알린다.
- **Claude Code 버전.** 필요한 플러그인 기능(`$.ui.open` / `$.command.run` / `$.session.append` / `$.store` / `$.clock`)은 2.1.330에서 확인했다. 최소 버전은 만드는 사람이 확인해 README에 기록한다.

## 동작 흐름

### `/side [질문]`

Claude가 일하는 중이면 먼저 입력창 위에 `작업이 끝나면 곁가지로 가요`를 띄우고, 작업이 끝난 뒤에 아래 순서를 진행한다. 사용자가 Esc로 멈추면 5초쯤 다시 시도하고, 그래도 받아들여지지 않으면 입력창에 `/side <질문>`을 채우고 `Esc로 멈춘 뒤라 바로 가르지 못했어요. Enter를 누르면 곁가지로 가요`를 알린다. 작업 중에도 명령이 바로 받아지도록 등록해야 한다(`immediate`). 갈라지는 지점은 `/side`를 친 순간이 아니라 실제로 갈라지는 순간의 마지막 메시지다.

1. 지금 세션 ID와 마지막 메시지 ID를 곁가지 기록으로 남긴다. 제목은 질문 앞부분이고, 질문이 없으면 시각으로 정한다.
2. 대기열에 `/branch`를 추가한다. 타이머가 실행한 뒤 새 세션 ID를 기록에 채운다.
3. 질문이 있으면 곁가지에서 그 질문을 첫 프롬프트로 보낸다.
4. 입력창 위 한 줄에 `곁가지: <제목> | /back 으로 메인에 돌아가기`를 띄운다.

### `/back`

1. 지금 세션이 곁가지인지 확인한다. 플러그인 기록을 먼저 보고, 없으면 `forkedFrom`을 본다. 둘 다 없으면 돌아갈 곳이 없다고 알리고 끝낸다.
2. 대기열에 `/resume <메인 세션 ID>`를 추가한다. Claude가 일하는 중이면 작업이 끝난 뒤 실행된다.
3. 돌아오면 기록에 돌아왔다는 표시를 남긴다. 곁가지에서 바뀐 파일이 있으면 목록과 함께 파일은 그대로 남는다고 알린다. 곁가지에 있는 동안 메인이 진행됐으면 그것도 알린다.

곁가지의 곁가지에서 `/back`을 하면 한 단계 위 곁가지로 돌아간다. 메인에서 `/back`을 하면 아무것도 하지 않고 돌아갈 곳이 없다고 알린다.

### `/tree`

옆 칸에 지금 세션이 속한 나무 하나를 맨 위 조상부터 그린다. 다른 나무와 곁가지가 없는 세션은 제외한다. 세션 전체 목록은 `/resume`에서 볼 수 있다. 지금 있는 세션을 표시하고, 가지마다 제목, 만든 시각, 돌아왔는지 여부를 보여 준다. 가지를 고르면 대기열에 `/resume <ID>`를 넣어 그 세션으로 이동한다. 가지마다 `이름 바꾸기` 버튼이 있어서, 누르면 그 줄이 입력 칸으로 바뀌고 Enter로 새 이름을 저장한다(30자까지, 비우면 그대로). 맨 위 메인 줄도 바꿀 수 있고, 그 이름은 `name:<세션 ID>`로 따로 저장한다.

## 기록

`$.store`(세션을 넘어 유지되는 저장소)에 곁가지 기록을 하나씩 따로 둔다(`rec:<세션 ID>`). 키 하나에 목록 전체를 쓰면 창 두 개가 서로의 기록을 덮어쓰기 때문이다. 기록끼리는 프로젝트 폴더가 아니라 세션 ID로 연결한다. 그래서 프로젝트 루트를 따로 정의할 필요가 없다.

| 필드 | 뜻 |
|---|---|
| `id` | 곁가지 세션 ID |
| `parentSessionId`, `parentMessageUuid` | 갈라진 세션과 메시지 |
| `title` | 질문 앞부분 |
| `createdAt` | 만든 시각 |
| `status` | 열림 또는 돌아옴. 돌아온 곁가지에 다시 들어가면 열림으로 바뀐다 |
| `changedFiles` | 곁가지에서 바뀐 파일 |

## 내가 정한 것

사용자가 고칠 수 있는 제안이다.

- 명령 이름은 `/side`, `/back`, `/tree`로 한다. 다른 플러그인과 겹치면 앞에 접두어를 붙인다.
- 평소에는 입력창 위 한 줄만 보여 주고, 나무는 `/tree`로 연다(옆 칸 144칸 제약 때문).
- `/side`로 만든 가지는 플러그인 기록을 기준으로 삼고, 세션 기록 파일의 `forkedFrom`은 보조로만 쓴다.
- 곁가지에서 바뀐 파일은 되돌리지 않고 `/back` 때 목록만 보여 준다.
- 메인에 남는 `/side` 입력 줄은 받아들인다. 그 출력은 모델이 읽지 않게 한다.
- `/tree`는 지금 세션이 속한 나무 하나만 보여 준다. 기록끼리는 세션 ID로 연결한다.
- 언어는 TypeScript(Claude Code 플러그인 규약), 라이선스는 MIT, README는 영어를 기본으로 하고 한국어 README를 따로 둔다.

## 저장소 구성

```
detour/
  core/                  공통 부분: 기록 형식, 나무 계산
  plugins/claude-code/   A: .claude-plugin/plugin.json, hooks/, types/
  plugins/orca/          B: 나중에 만든다
  docs/superpowers/specs/
```

Claude Code 플러그인 모듈은 Node 기능 없이 엔진이 주는 `$`로만 동작한다. `core/`를 두 플러그인이 어떻게 함께 쓸지(상대 경로 import가 되는지, 빌드 때 복사하는지)는 만드는 사람이 확인한다.

## 시험 방법

- 기록 계산과 대기열은 `claude plugin test`로 단위 시험한다.
- 실제 왕복은 시험용 플러그인 때처럼 별도 Claude Code를 가상 터미널로 띄워 확인한다. 이때 주의할 점이 두 가지 있다.
  - Claude Code 안에서 띄우면 `CLAUDE_CODE_CHILD_SESSION` 같은 환경 변수가 넘어가 세션 기록이 저장되지 않는다. `CLAUDE`, `AI_AGENT`로 시작하는 환경 변수를 지우고 띄워야 한다.
  - 처음 보는 폴더면 신뢰 확인 창이 뜨고 기본 선택이 "No, exit"다. 아래 화살표 뒤 Enter를 보내야 한다.
- 시험이 끝나면 시험 폴더와 `~/.claude/projects` 아래 시험 세션 기록을 지운다.

## B. Orca 플러그인 (A 다음)

A가 나온 뒤 따로 설계한다. 지금 알고 있는 것만 기록한다.

- Orca 1.4.191(`com.stablyai.orca`) 플러그인은 `orca-plugin.json`으로 칸(`contributes.panels`)을 추가할 수 있다.
- 플러그인이 받을 수 있는 권한 가운데 쓸 만한 것:
  - `terminal:send`: 보이는 터미널에 글자 입력
  - `workspace:read`: 지금 작업 공간의 이름과 브랜치, 터미널 목록 읽기
  - `events:subscribe`: 작업 공간 생성과 삭제, 에이전트 상태 변화 알림
- 칸에서 가지를 누르면 해당 터미널에 `/resume <ID>`를 입력하는 방식으로 이동할 수 있어 보인다.
- 확인하지 못한 것: 권한 목록에 자기 폴더 밖 파일 읽기가 없어서, Orca 칸이 Claude Code 세션 기록이나 A의 기록을 직접 읽지 못할 수 있다. B를 시작할 때 이것부터 시험한다.
- B는 A가 설치되어 있어야 동작한다.

## 만드는 사람에게 맡기는 것

- 입력창 위 한 줄과 옆 칸의 세부 모양, 키보드 조작
- 대기열과 타이머의 세부 구현
- `core/` 공유 방법
- 시험 파일 구조
